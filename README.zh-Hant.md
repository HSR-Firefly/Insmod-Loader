# Insmod Loader

一個 KernelSU 模塊：開機時按你指定的順序，用 `insmod` 加載指定的內核模塊（`.ko`）。

具有簡單的配置文件系統，可以控制加載的模塊以及加載順序。

## 安裝方法

1. 在 KernelSU 管理器裏刷入該模塊
2. 重啓一次（讓安裝腳本把目錄建好）


## 使用方法

裝完重啓後，手機上會多出這個目錄：

```txt
/data/adb/insmod-loader/
├── post-fs-data/     # 開機很早的階段（會拖慢開機，少用）
├── late_start/       # 開機稍晚的階段（推薦用這個）
└── logs/             # 日誌
```

**第 1 步：把 `.ko` 放進去**

將要加載的內核模塊放入/data/adb/insmod-loader/post-fs-data 或 /data/adb/insmod-loader/late_start，然後將其加入對應目錄的配置文件

**第 2 步：在同一個目錄的 `config.txt` 裏登記**（沒登記的模塊不會被加載）

```txt
#語法:模塊:執行優先級(1-999)
mydriver.ko:100
```

- 一行一個，格式是 `文件名:優先級`
- 優先級 `1-999`，**數字越大越先加載**（`900` 排在 `100` 前面）
- 數字一樣時，按寫的先後順序加載
- `#` 開頭的行爲註釋

**第 3 步：重啓，然後確認**

```sh
adb shell 'su -c "lsmod | grep mydriver"'
```

## 出問題了怎麼看

想讓腳本把過程寫下來，先建一個空文件當開關（刪掉它就關掉日誌）：

```sh
adb shell 'su -c "touch /data/adb/insmod-loader/logs/debug"'
```

重啓後看日誌：

```sh
adb shell 'su -c "cat /data/adb/insmod-loader/logs/late_start.txt"'
```

日誌裏會寫明每個模塊加載成功還是失敗。如果配置有問題，也會直接寫清楚哪一行錯在哪。

> 日誌文件每次運行都會被覆蓋，只保留最近一次開機的結果。`post-fs-data` 階段的日誌可能因爲此時 `/data` 還沒準備好而寫不出來；排查早期問題請優先用 KernelSU 管理器自帶的模塊日誌。

**配置寫錯時，一個模塊都不會加載**（寧可不動，也不猜你的意思）。常見原因：

| 你寫的 | 爲什麼不行 |
|---|---|
| `mydriver.ko:1000` | 優先級只能是 1-999 |
| `mydriver.ko:abc` | 優先級必須是數字 |
| `mydriver.ko` | 少了冒號和優先級 |
| `lib/mydriver.ko:100` | 只能寫文件名，不能帶路徑 |
| `typo.ko:100` | 這個文件在目錄裏不存在 |
| `mydriver.zip:100` | 只認 `.ko` 結尾的文件 |

單個模塊加載失敗（比如內核版本不匹配）**不算配置錯誤**，其它模塊會照常加載。

## 兩個階段該選哪個

| | `post-fs-data/` | `late_start/` |
|---|---|---|
| 什麼時候跑 | 開機很早（系統服務還沒起來） | 開機稍晚，和系統啓動並行 |
| 影響開機嗎 | **會阻塞開機**（最多 10 秒） | 不影響 |
| 什麼時候用 | 模塊必須比 Zygote 更早加載 | 其它所有情況（**默認選這個**） |

## 注意

- **加載和內核不匹配的 `.ko` 會直接死機、甚至開不了機。** 確認模塊是爲你這臺設備的內核編譯的，並準備好救磚手段。
- 模塊只會被「加載」，不會被卸載。把某行從 `config.txt` 刪掉，只是下次開機不再加載它，本次開機已經加載的還在。
- 卸載這個模塊後，`/data/adb/insmod-loader` 裏的東西（你的 `.ko` 和配置）**不會被刪**——那是你自己的文件，模塊不替你清理。

## 倉庫結構

```txt
├── module/                 # 模塊本體（打包時進 zip 的就是這裏）
├── tests/                  # 測試，不進 zip
├── output/                 # 打包產物
├── pack.sh                 # 打包: ./pack.sh
├── README.md               # 你正在看的這份（給人看）
└── README_AGENTS.md        # 詳細實現說明、安全約定、測試清單（給改代碼的人/AI 看）
```
