# Insmod Loader

<!-- README-I18N:START -->
[繁體中文](./README.zh-Hant.md)
<!-- README-I18N:END -->

一个 KernelSU 模块：开机时按你指定的顺序，用 `insmod` 加载指定的内核模块（`.ko`）。

具有简单的配置文件系统，可以控制加载的模块以及加载顺序。

## 安装方法

1. 在 KernelSU 管理器里刷入该模块
2. 重启一次（让安装脚本把目录建好）


## 使用方法

装完重启后，手机上会多出这个目录：

```txt
/data/adb/insmod-loader/
├── post-fs-data/     # 开机很早的阶段（会拖慢开机，少用）
├── late_start/       # 开机稍晚的阶段（推荐用这个）
└── logs/             # 日志
```

**第 1 步：把 `.ko` 放进去**

将要加载的内核模块放入/data/adb/insmod-loader/post-fs-data 或 /data/adb/insmod-loader/late_start，然后将其加入对应目录的配置文件

**第 2 步：在同一个目录的 `config.txt` 里登记**（没登记的模块不会被加载）

```txt
#语法:模块:执行优先级(1-999)
mydriver.ko:100
```

- 一行一个，格式是 `文件名:优先级`
- 优先级 `1-999`，**数字越大越先加载**（`900` 排在 `100` 前面）
- 数字一样时，按写的先后顺序加载
- `#` 开头的行为注释

**第 3 步：重启，然后确认**

```sh
adb shell 'su -c "lsmod | grep mydriver"'
```

## 出问题了怎么看

想让脚本把过程写下来，先建一个空文件当开关（删掉它就关掉日志）：

```sh
adb shell 'su -c "touch /data/adb/insmod-loader/logs/debug"'
```

重启后看日志：

```sh
adb shell 'su -c "cat /data/adb/insmod-loader/logs/late_start.txt"'
```

日志里会写明每个模块加载成功还是失败。如果配置有问题，也会直接写清楚哪一行错在哪。

> 日志文件每次运行都会被覆盖，只保留最近一次开机的结果。`post-fs-data` 阶段的日志可能因为此时 `/data` 还没准备好而写不出来；排查早期问题请优先用 KernelSU 管理器自带的模块日志。

**配置写错时，一个模块都不会加载**（宁可不动，也不猜你的意思）。常见原因：

| 你写的 | 为什么不行 |
|---|---|
| `mydriver.ko:1000` | 优先级只能是 1-999 |
| `mydriver.ko:abc` | 优先级必须是数字 |
| `mydriver.ko` | 少了冒号和优先级 |
| `lib/mydriver.ko:100` | 只能写文件名，不能带路径 |
| `typo.ko:100` | 这个文件在目录里不存在 |
| `mydriver.zip:100` | 只认 `.ko` 结尾的文件 |

单个模块加载失败（比如内核版本不匹配）**不算配置错误**，其它模块会照常加载。

## 两个阶段该选哪个

| | `post-fs-data/` | `late_start/` |
|---|---|---|
| 什么时候跑 | 开机很早（系统服务还没起来） | 开机稍晚，和系统启动并行 |
| 影响开机吗 | **会阻塞开机**（最多 10 秒） | 不影响 |
| 什么时候用 | 模块必须比 Zygote 更早加载 | 其它所有情况（**默认选这个**） |

## 注意

- **加载和内核不匹配的 `.ko` 会直接死机、甚至开不了机。** 确认模块是为你这台设备的内核编译的，并准备好救砖手段。
- 模块只会被「加载」，不会被卸载。把某行从 `config.txt` 删掉，只是下次开机不再加载它，本次开机已经加载的还在。
- 卸载这个模块后，`/data/adb/insmod-loader` 里的东西（你的 `.ko` 和配置）**不会被删**——那是你自己的文件，模块不替你清理。
